# NaturalTravel — Backend 🌿

Backend частина **NaturalTravel** — вебплатформи для публікації, перегляду та збереження історій подорожей Україною.

Проєкт побудований на Node.js та Express і використовує MongoDB для зберігання даних. REST API забезпечує взаємодію між frontend-застосунком і серверною частиною.

## 🛠️ Технології

| Технологія | Призначення                                      |
| ---------- | ------------------------------------------------ |
| Node.js    | Середовище виконання JavaScript                  |
| Express 5  | Створення REST API                               |
| MongoDB    | Документна база даних                            |
| Mongoose   | Робота з моделями та даними MongoDB              |
| Celebrate  | Валідація HTTP-запитів                           |
| Cloudinary | Робота з медіафайлами                            |
| Multer     | Обробка завантаження файлів                      |
| Helmet     | Захисні HTTP-заголовки                           |
| bcrypt     | Хешування паролів                                |
| Nodemon    | Автоматичний перезапуск сервера під час розробки |

## 🚀 Початок роботи

### Передумови

Для локального запуску потрібні:

- [Node.js](https://nodejs.org/) — версія LTS, сумісна з проєктом.
- npm.
- Доступ до бази даних MongoDB Atlas.
- Дозвіл на підключення вашої публічної IP-адреси в MongoDB Atlas.

### 1. Клонування репозиторію

```powershell
git clone https://github.com/Iv-Hl/project-NaturalTravel.git
cd project-NaturalTravel
```

### 2. Встановлення залежностей

```powershell
npm ci
```

Виконуйте команду в директорії, де розташований `package.json` backend-проєкту.

### 3. Налаштування середовища

Якщо файл `.env` ще не існує, створіть його на основі `.env.example`:

```powershell
if (-not (Test-Path .env)) {
  Copy-Item .env.example .env
}
```

Налаштуйте змінні у файлі `.env`:

```dotenv
MONGODB_URL="your_personal_connection_string"
PORT=3000
CORS_ORIGINS=http://localhost:3001
```

Отримайте рядок підключення до MongoDB Atlas від керівника команди. Передайте йому свою публічну IP-адресу для додавання до списку дозволених адрес бази даних.

Перевірте `.env.example` на наявність інших необхідних змінних.

### 4. Запуск сервера

```powershell
npm run dev
```

Після успішного підключення до бази даних у терміналі мають з'явитися повідомлення, подібні до таких:

```text
Connected to MongoDB
Server is running on http://localhost:3000
```

| --------------- | --------------------------- |
| Backend         | `http://localhost:3000`     |
| Базовий URL API | `http://localhost:3000/api` |

## 📡 API Endpoints

Базова адреса API:

`http://localhost:3000/api`

Ендпойнти поділяються на **публічні**, доступні без авторизації, та **приватні**, для яких потрібна авторизація користувача.

Наведені нижче маршрути є документацією запланованого API відповідно до технічного завдання. Точні шляхи й методи потрібно звірити з реалізацією в репозиторії.

### 1. Авторизація — `/api/auth`

| Метод  | Ендпойнт             | Доступ    | Призначення                   |
| ------ | -------------------- | --------- | ----------------------------- |
| `POST` | `/api/auth/register` | Публічний | Реєстрація нового користувача |
| `POST` | `/api/auth/login`    | Публічний | Вхід користувача в систему    |
| `POST` | `/api/auth/logout`   | Приватний | Вихід користувача із системи  |
| `POST` | `/api/auth/refresh`  | Приватний | Перевірка та оновлення сесії  |

Для приватних маршрутів сервер перевіряє автентифікацію користувача за допомогою відповідного middleware.

### 2. Користувачі — `/api/users`

| Метод    | Ендпойнт                               | Доступ    | Призначення                                                                    |
| -------- | -------------------------------------- | --------- | ------------------------------------------------------------------------------ |
| `GET`    | `/api/users/:userId`                   | Публічний | Отримання інформації про користувача та його опубліковані історії з пагінацією |
| `GET`    | `/api/users/me`                        | Приватний | Отримання інформації про поточного користувача                                 |
| `GET`    | `/api/users/me/stories`                | Приватний | Отримання власних історій користувача з пагінацією                             |
| `GET`    | `/api/users/me/saved-stories`          | Приватний | Отримання збережених історій із пагінацією                                     |
| `POST`   | `/api/users/me/saved-stories/:storyId` | Приватний | Додавання історії до збережених                                                |
| `DELETE` | `/api/users/me/saved-stories/:storyId` | Приватний | Видалення історії зі збережених                                                |

#### Додаткові можливості користувачів

Ці маршрути передбачені як додаткові завдання та можуть бути реалізовані пізніше.

| Метод   | Ендпойнт               | Доступ    | Призначення                   |
| ------- | ---------------------- | --------- | ----------------------------- |
| `PATCH` | `/api/users/me/avatar` | Приватний | Оновлення аватара користувача |
| `PATCH` | `/api/users/me`        | Приватний | Оновлення даних користувача   |

Оновлення електронної пошти має передбачати верифікацію через лист на адресу, яку користувач намагається змінити.

### 3. Історії подорожей — `/api/stories`

| Метод  | Ендпойнт                                | Доступ    | Призначення                                                                 |
| ------ | --------------------------------------- | --------- | --------------------------------------------------------------------------- |
| `GET`  | `/api/stories`                          | Публічний | Отримання історій із фільтрацією, пагінацією та вибіркою популярних історій |
| `GET`  | `/api/stories/:storyId`                 | Публічний | Отримання детальної інформації про історію                                  |
| `GET`  | `/api/stories/:storyId/recommendations` | Публічний | Отримання рекомендованих історій із пагінацією                              |
| `POST` | `/api/stories`                          | Приватний | Створення нової історії поточним користувачем                               |

#### Параметри запитів

Для списків історій передбачається використання таких query-параметрів:

| Параметр       | Призначення                     |
| -------------- | ------------------------------- |
| `page`         | Номер сторінки                  |
| `limit`        | Кількість елементів на сторінці |
| `category`     | Фільтрація за категорією        |
| `type=popular` | Отримання популярних історій    |

Приклад запиту на отримання популярних історій:

```http
GET /api/stories?type=popular&limit=10&page=1
```

**Популярні історії** визначаються за кількістю додавань до збережених іншими користувачами, а не лише за рейтингом.

**Рекомендовані історії** — це історії відповідної категорії з найбільшою кількістю додавань до збережених. Для них також передбачена пагінація.

Фактичні назви параметрів і правила сортування мають відповідати реалізації backend.

### Статус реалізації API

API перебуває в активній розробці. Наявність ендпойнта в цій документації не означає, що його реалізація вже завершена.

Деякі маршрути можуть повертати `501 Not Implemented`, якщо відповідна функціональність ще не реалізована.

| Змінна         | Опис                                          |
| -------------- | --------------------------------------------- |

Для інтеграцій та інших функцій можуть знадобитися додаткові змінні. Повний перелік параметрів перевіряйте у `.env.example`.

## 🔒 Безпека

- Зберігайте конфіденційні дані лише в локальних змінних середовища.
- Не додавайте `.env` та інші файли із секретами до Git.
- Обмежуйте доступ до MongoDB Atlas авторизованими IP-адресами.
- Не публікуйте ключі Cloudinary та інші приватні облікові дані.
- Використовуйте окремі конфігурації для локального середовища та production.
- Не запускайте `npm audit fix --force` без погодження з командою.
